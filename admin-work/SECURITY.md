## حماية الواجهة

- **سياسة أمان المحتوى (CSP)** بمعرّف nonce لكل طلب، و`frame-ancestors 'none'`، وX-Frame-Options: DENY، وnosniff، وHSTS، وReferrer-Policy، ولا تُكشف ترويسة X-Powered-By.
- **النصوص المخزنة الخبيثة (XSS)**: React يهرّب كل النصوص. الموضع الوحيد الذي يُدرج HTML (عرض التقرير) يمر من دالة تهريب `renderReportHtml` مع اختبار مخصص. فحص المتصفح يحقن `<img onerror>` و`<script>` في الأسماء والأوصاف ويتحقق من عدم تنفيذهما في 8 صفحات.
- **الطلبات من مواقع خارجية (CSRF)**: Next.js يرفض الإجراءات الخادمية القادمة من مصدر مختلف، وملف الجلسة SameSite=Lax. واجهات التنزيل للقراءة فقط.
- **إعادة التوجيه المفتوح**: رابط فتح التنبيه يقبل المسارات الداخلية فقط.

## ملفات Excel

- **الاستيراد**: حد 5 ميغابايت و5000 صف، وفحص توقيع الملف الحقيقي (xlsx)، وقراءة الصيغ كقيمها المحسوبة فقط، والتحقق من كل حقل قبل الحفظ.
- **التصدير**: كل القيم تُكتب نصوصاً لا صيغاً، فلا تُنفَّذ أسماء تبدأ بـ `=` عند فتح الملف (مختبر).

## المهمة المجدولة

`POST /api/cron/notifications` محمية بسر `CRON_SECRET` (16 حرفاً على الأقل) مع مقارنة ثابتة الزمن.

## ثغرات المكتبات المعروفة (`npm audit`) — تقييم بتاريخ 2026-11-03

يبلغ `npm audit` عن 15 تنبيهاً (5 عالية و10 متوسطة). علاجها كلها يتطلب ترقيات رئيسية تكسر التوافق (Next 16، Prisma 7، Zod 4، وexceljs). لا يصل أي منها إلى مدخلات المستخدم في طريقة استخدام النظام:

| المكتبة | الثغرة | لماذا لا تؤثر حالياً |
|---|---|---|
| postcss (عبر next) | معالجة CSS غير موثوق | تعالج CSS الخاص بالنظام وقت البناء فقط، ولا يُقبل CSS من المستخدمين |
| prisma، ‏@prisma/config، ‏deepmerge-ts | استنزاف المكدس عند دمج كائنات متداخلة | أداة إعداد وترحيل، لا تستقبل مدخلات المستخدم |
| exceljs وتوابعها (archiver، ‏minimatch، ‏glob، ‏uuid) | حجب خدمة بأنماط glob، وفحص حدود uuid | الأنماط ثابتة داخل المكتبة، ولا يُمرَّر buffer إلى uuid |
| zod | استنزاف الذاكرة عند التحقق من مجموعات ضخمة | المصفوفة الوحيدة (صلاحيات المستخدم) تُقص إلى 40 عنصراً قبل التحقق، وهي متاحة للمدير بعد الدخول فقط. حجم جسم الطلب محدود بـ 7 ميغابايت |

**التوصية:** خطة ترقية مستقلة إلى Next 16 وZod 4 وPrisma 7 بعد الإطلاق، مع إعادة تشغيل كل الاختبارات. يُعاد تشغيل `npm audit` قبل كل نشر.

## قبل التشغيل الفعلي

- ضبط `APP_SECRET` و`CRON_SECRET` و`BACKUP_KEY` بقيم عشوائية قوية، وحفظ `BACKUP_KEY` خارج الخادم (بدونه لا تُستعاد النسخ).
- تشغيل النظام خلف HTTPS حصراً.
- جدولة `npm run backup` يومياً، وتجربة الاستعادة دورياً على قاعدة منفصلة.
- منح حساب قاعدة البيانات الذي يتصل به التطبيق صلاحيات البيانات فقط (دون SUPERUSER)، حتى لا يستطيع تعطيل مشغّلات الحماية.
