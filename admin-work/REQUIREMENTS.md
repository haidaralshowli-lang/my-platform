# وثيقة المتطلبات (كما وردت من صاحب المشروع)

```text
مشروع: نظام إدارة العمل الإداري والتنظيمي
1. فكرة المشروع
أريد بناء منصة إلكترونية إدارية متكاملة باللغة العربية، تعمل على الحاسوب والموبايل، لإدارة العمل الإداري والتنظيمي، وتنظيم قاعدة بيانات الأشخاص، وإدارة الطلبات الواردة، وتوزيع المهام، ومتابعة الإنجاز، وإصدار التقارير الإدارية.
يجب أن تكون المنصة عملية وبسيطة، وتقلل الاعتماد على المتابعة الهاتفية والرسائل العشوائية، وتوفر رؤية واضحة للإدارة عن حجم العمل والطلبات والمهام ومستوى الإنجاز.
2. أهداف النظام
1. إنشاء قاعدة بيانات موحدة للأشخاص.
2. متابعة اكتمال وتحديث البيانات.
3. تنظيم استقبال الطلبات وتصنيفها ومتابعتها.
4. توزيع المهام على أعضاء الفريق وفق موافقتهم وقدرتهم.
5. معرفة المهام المنجزة والمتأخرة والمتعثرة.
6. تقليل الضغط الإداري على مدير العمل.
7. توفير تقارير يومية وأسبوعية وشهرية.
8. حفظ سجل تاريخي لجميع الإجراءات والتحديثات.
3. الهيكل الإداري والصلاحيات
يحتوي النظام على مستويين أساسيين من المستخدمين:
أولاً: مدير النظام / مدير العمل
يمتلك الصلاحيات الكاملة، ومنها:
- الاطلاع على جميع البيانات.
- إضافة وتعديل وحذف السجلات وفق الصلاحيات المعتمدة.
- إدارة قاعدة البيانات.
- الاطلاع على جميع الطلبات.
- توزيع المهام ومتابعتها.
- اعتماد إغلاق الطلبات والمهام.
- مشاهدة التقارير والإحصائيات.
- إدارة حساب المنسق العام.
ثانياً: المنسق العام
يمتلك صلاحيات تشغيلية يحددها المدير، ومنها:
- إضافة الأشخاص وتحديث بياناتهم.
- تسجيل الطلبات الجديدة.
- متابعة الطلبات وحالاتها.
- تسجيل المهام وتحديث مراحل الإنجاز.
- إعداد التقارير.
- الاطلاع على لوحة المتابعة.
لا يُسمح للمنسق العام بتغيير صلاحيات المدير أو إنشاء مدير آخر.
لا توجد حسابات عامة أو تسجيل ذاتي، ولا يسمح بالوصول إلى النظام دون مصادقة.
4. لوحة التحكم الرئيسية Dashboard
تصميم لوحة تحكم تعرض المؤشرات التالية:
مؤشرات الأشخاص
- إجمالي عدد السجلات.
- عدد البيانات المكتملة.
- عدد البيانات الناقصة.
- عدد السجلات التي تحتاج إلى تحديث.
- عدد الأشخاص المتاحين للتعاون الإداري.
مؤشرات الطلبات
- إجمالي الطلبات.
- الطلبات الجديدة.
- الطلبات قيد المراجعة.
- الطلبات قيد المتابعة.
- الطلبات المنجزة.
- الطلبات المتعذرة.
- الطلبات المتأخرة عن موعد المتابعة.
مؤشرات المهام
- إجمالي المهام.
- المهام الجديدة.
- المهام قيد التنفيذ.
- المهام المنجزة.
- المهام المتعثرة.
- نسبة الإنجاز العامة.
تكون المؤشرات تفاعلية، بحيث يؤدي الضغط على أي مؤشر إلى فتح السجلات المرتبطة به.
5. إدارة قاعدة بيانات الأشخاص
إنشاء صفحة مستقلة لإدارة قاعدة البيانات، تتضمن الحقول التالية:
- رقم تسلسلي تلقائي.
- الاسم الكامل.
- رقم الهاتف، عند الحاجة.
- المحافظة أو المنطقة.
- مسؤول المتابعة.
- تاريخ إضافة السجل.
- حالة اكتمال البيانات.
- مستوى التفاعل الإداري.
- المهام التي وافق الشخص على تنفيذها.
- تاريخ آخر تحديث.
- ملاحظات إدارية غير حساسة.
حالات البيانات:
- مكتملة.
- ناقصة.
- بانتظار التحديث.
إمكانية البحث بالاسم أو الرقم أو المنطقة أو مسؤول المتابعة.
إمكانية استيراد البيانات من Excel وتصديرها إلى Excel.
منع تكرار السجلات، مع إمكانية اكتشاف الأسماء المتشابهة ومراجعتها قبل الدمج.
6. إدارة الطلبات
إنشاء وحدة متكاملة لاستقبال الطلبات ومتابعتها.
بيانات الطلب:
- رقم الطلب التلقائي.
- تاريخ الاستلام.
- اسم مقدم الطلب.
- نوع الطلب.
- وصف الطلب.
- الجهة المختصة.
- المسؤول عن المتابعة.
- درجة الأولوية.
- آخر إجراء.
- موعد المتابعة.
- تاريخ الإغلاق.
- سبب التعذر عند وجوده.
أنواع الطلبات:
- طلب إداري.
- طلب خدمي عام.
- استفسار.
- متابعة معاملة.
- طلب آخر.
حالات الطلب:
1. جديد.
2. قيد المراجعة.
3. محال إلى الجهة المختصة.
4. قيد المتابعة.
5. منجز.
6. متعذر.
7. مغلق.
إضافة سجل زمني لكل طلب يوضح جميع الإجراءات التي تمت عليه، ومن قام بها وتاريخها.
إمكانية البحث والتصفية حسب النوع والحالة والتاريخ والمسؤول.
إمكانية استخراج كشف بالطلبات المتأخرة.
مهم: تسجيل الطلب ومتابعته لا يعني ضمان تحقيقه، ويجب أن يعرض النظام حالة الطلب الحقيقية دون وعود تلقائية بالإنجاز.
7. إدارة المهام
إنشاء وحدة خاصة بتوزيع ومتابعة المهام.
بيانات المهمة:
- رقم المهمة.
- عنوان المهمة.
- تفاصيل المهمة.
- الشخص المكلف.
- تاريخ التكليف.
- الموعد المحدد.
- الأولوية.
- حالة المهمة.
- نسبة الإنجاز.
- آخر تحديث.
- المعوقات.
- النتيجة النهائية.
حالات المهمة:
- لم تبدأ.
- قيد التنفيذ.
- بانتظار رد.
- منجزة.
- متعثرة.
- ملغاة.
مبدأ أساسي:
لا تتحول المهمة إلى تكليف نافذ إلا بعد موافقة الشخص على تنفيذها والمدة الزمنية المحددة يجب أن يتمكن المسؤول من تسجيل اعتذاره أو طلب تعديل الموعد، مع توثيق ذلك.
8. نظام الإشعارات والتنبيهات
إضافة تنبيهات داخل النظام عند:
- تسجيل طلب جديد.
- اقتراب موعد متابعة طلب.
- تأخر طلب عن موعده.
- إسناد مهمة جديدة.
- اقتراب موعد إنجاز المهمة.
- تأخر إنجاز المهمة.
- عدم تحديث سجل لفترة محددة.
9. التقارير الإدارية
إعداد تقارير قابلة للطباعة والتصدير PDF وExcel.
التقارير المطلوبة:
1. تقرير قاعدة البيانات.
2. تقرير اكتمال البيانات.
3. تقرير الطلبات المستلمة.
4. تقرير الطلبات المنجزة والمتأخرة.
5. تقرير المهام المسندة والمنجزة.
6. تقرير المعوقات.
7. التقرير الأسبوعي الشامل.
8. التقرير الشهري الشامل.
يجب أن تحتوي التقارير على الفترة الزمنية وتاريخ إعداد التقرير وإحصائيات واضحة.
10. سجل الإجراءات Audit Log
إنشاء سجل تدقيق يسجل:
- المستخدم الذي أجرى التعديل.
- نوع العملية.
- السجل الذي تم تعديله.
- تاريخ ووقت العملية.
- القيمة السابقة والجديدة عند تعديل البيانات المهمة.
لا يسمح للمستخدم العادي بحذف سجل التدقيق.
11. التصميم وتجربة الاستخدام
- اللغة العربية بالكامل.
- اتجاه الكتابة RTL.
- تصميم إداري احترافي وبسيط.
- واجهة متوافقة مع الحاسوب والموبايل.
- قوائم واضحة وسهلة الاستخدام.
- ألوان هادئة ومناسبة للعمل الإداري.
- جداول قابلة للبحث والفرز والتصفية.
- نوافذ إدخال منظمة.
- دعم الطباعة والتصدير.
- سرعة في تحميل الصفحات.
12. الحماية والخصوصية
- تسجيل دخول آمن.
- صلاحيات حسب نوع المستخدم.
- حماية قاعدة البيانات.
- نسخ احتياطي دوري.
- عدم إظهار البيانات للمستخدمين غير المخولين.
- عدم جمع معلومات حساسة أو غير ضرورية.
- عدم استخدام البيانات في التقييم السياسي أو الاستنتاجات المتعلقة بآراء الأشخاص أو تفضيلاتهم.
- حفظ جميع عمليات الدخول والتعديل.
- توفير آلية لاستعادة البيانات عند حدوث خطأ.
13. المتطلبات التقنية
اختر بنية تقنية حديثة ومستقرة تدعم:
- قاعدة بيانات علائقية.
- واجهة Frontend متجاوبة.
- Backend آمن.
- نظام مصادقة وصلاحيات.
- استيراد وتصدير Excel.
- تصدير التقارير PDF.
- نسخ احتياطي واستعادة.
- إمكانية تطوير النظام مستقبلاً.
يجب أن تكون قاعدة البيانات مركزية، وليس مجرد تخزين محلي داخل المتصفح.
14. مراحل التنفيذ
نفذ المشروع على مراحل:
المرحلة الأولى:
إنشاء قاعدة البيانات ونظام تسجيل الدخول والصلاحيات.
المرحلة الثانية:
إنشاء لوحة التحكم وإدارة الأشخاص.
المرحلة الثالثة:
إنشاء إدارة الطلبات والمهام.
المرحلة الرابعة:
إنشاء التقارير والإشعارات.
المرحلة الخامسة:
اختبار الصلاحيات والحماية والاستيراد والتصدير.
المرحلة السادسة:
اختبار النظام على الحاسوب والموبايل وتجهيز النسخة النهائية للنشر.
15. تعليمات مهمة للمطور
لا أريد نموذجاً شكلياً أو واجهات تجريبية فقط.
أريد نظاماً فعلياً يعمل بقاعدة بيانات حقيقية، مع عمليات إضافة وتعديل وبحث وحفظ وحذف مؤمنة حسب الصلاحيات.
ابدأ بتصميم قاعدة البيانات ومخطط العلاقات بين الجداول، ثم أنشئ النظام تدريجياً.
لا تستخدم بيانات وهمية في النسخة النهائية.
لا تنتقل إلى المرحلة التالية قبل اختبار المرحلة الحالية.
أريد في النهاية منصة إدارية متكاملة قابلة للتشغيل الفعلي والتطوير المستقبلي.
```
