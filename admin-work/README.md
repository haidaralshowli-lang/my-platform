# نظام إدارة العمل الإداري والتنظيمي

منصة عربية (RTL) تعمل على الحاسوب والموبايل لإدارة قاعدة بيانات الأشخاص، والطلبات الواردة، وتوزيع المهام بموافقة المكلفين، ومتابعة الإنجاز، والتقارير الإدارية، مع سجل تدقيق كامل.

> هذا التطبيق مستقل عن منصة إدارة المخالفات الموجودة في جذر المستودع: له قاعدة بيانات وحزم وإعدادات خاصة به.

## حالة التنفيذ

| المرحلة | المحتوى | الحالة |
|---|---|---|
| 1 | قاعدة البيانات الكاملة ومخطط العلاقات، تسجيل الدخول، الأدوار والصلاحيات، إدارة المستخدمين، سجل التدقيق المحمي، القوائم المرجعية والإعدادات | ✅ مكتملة ومختبرة |
| 2 | لوحة المتابعة (مؤشرات الأشخاص التفاعلية والتوزيعات)، إدارة الأشخاص: إضافة وتعديل وبحث وفلاتر وفرز، سجل التعديلات لكل سجل، استيراد Excel بمعاينة صف بصف، تصدير Excel، كشف الأسماء المتشابهة والدمج، الحذف الناعم والاستعادة | ✅ مكتملة ومختبرة |

| 3 | الطلبات: ترقيم تلقائي، سير الحالات السبع، سجل زمني لكل إجراء، كشف المتأخرة وتصديره. المهام: موافقة المكلف قبل النفاذ، طلب تعديل الموعد، الاعتذار وإعادة الإسناد، مراحل الإنجاز والمعوقات، اعتماد الإغلاق. مؤشرات الطلبات والمهام في لوحة المتابعة | ✅ مكتملة ومختبرة |
| 4 | التنبيهات السبعة داخل النظام (فورية ودورية دون تكرار)، والتقارير الثمانية بعرض قابل للطباعة وتصدير PDF وExcel | ✅ مكتملة ومختبرة |
| 5 | مصفوفة الصلاحيات، 72 فحص أمان عبر HTTP، اختبارات الإدخال الخبيث والاستيراد والتصدير، النسخ الاحتياطي المشفّر والاستعادة المختبرة، استعادة الطلبات والمهام المحذوفة | ✅ مكتملة ومختبرة |
| 6 | النشر على Netlify + Supabase (مخطط وأدوار مستقلة)، والتحقق من النسخة المنشورة على الحاسوب والهاتف | ✅ منشور ومُتحقق منه: https://admin-work-platform.netlify.app |

لا يظهر أي قسم في القائمة قبل تنفيذه فعلياً (`IMPLEMENTED_PHASE` في `src/lib/nav.ts`).

## التشغيل محلياً

المتطلبات: Node.js 22.9 أو أحدث، وPostgreSQL 14 أو أحدث.

```bash
cd admin-work
npm ci
cp .env.example .env          # عدّل DATABASE_URL وAPP_SECRET
npm run db:migrate            # تطبيق الترحيلات
npm run db:seed               # المحافظات والإعدادات الافتراضية (لا يُنشئ أي حساب)
npm run admin:create          # إنشاء أول مدير نظام تفاعلياً
npm run dev                   # http://localhost:3100
```

لا توجد حسابات افتراضية ولا تسجيل ذاتي. بعد دخول المدير، ينشئ حساب المنسق العام من صفحة «المستخدمون والصلاحيات» ويحدد صلاحياته التشغيلية. تظهر كلمة المرور المؤقتة مرة واحدة، ويُلزَم صاحبها بتغييرها عند أول دخول.

## الأدوار

| | مدير النظام | المنسق العام |
|---|---|---|
| الصلاحيات | جميعها دائماً | الصلاحيات التشغيلية التي يمنحها المدير فقط |
| إدارة الحسابات والصلاحيات | ✅ | ❌ (لا يُنشئ مديراً ولا يعدّل حسابه) |
| اعتماد إغلاق الطلبات والمهام، والحذف، والدمج | ✅ | ❌ |
| القوائم المرجعية والإعدادات وسجل التدقيق | ✅ | ❌ |

تُفرض الصلاحيات في الخادم داخل كل صفحة وإجراء. وحتى لو عُدّلت صلاحيات المنسق مباشرة في قاعدة البيانات، يُسقط النظام أي صلاحية إدارية منها.

## قاعدة بيانات الأشخاص

- **حالة البيانات تُحتسب تلقائياً**: «مكتملة» عند تحديد المحافظة/المنطقة ومسؤول المتابعة، و«ناقصة» عند غياب أحدهما، و«بانتظار التحديث» إذا عُلِّم السجل بذلك. رقم الهاتف اختياري.
- **تحتاج إلى تحديث** (في اللوحة والفلتر): السجلات «بانتظار التحديث» أو التي لم تُعدَّل منذ عدد الأيام المحدد في الإعدادات (90 افتراضياً).
- **منع التكرار**: رقم الهاتف لا يتكرر مطلقاً. الاسم المطابق (بعد توحيد الهمزات والتاء المربوطة والتشكيل والمسافات) يُرفض إلا إذا أكد المستخدم أنه شخص مختلف، ويُحفظ هذا التأكيد. الأسماء المتشابهة تظهر أثناء الكتابة، وفي صفحة «مراجعة الأسماء المتشابهة».
- **الدمج** (للمدير): يُكمل الحقول الفارغة في السجل المُبقى عليه، وينقل إليه المهام والطلبات، ويحذف الآخر حذفاً ناعماً مع الإشارة إليه.
- **الاستيراد**: يُفحص الملف أولاً (الحقول، المحافظات، أسماء المستخدمين، التكرار داخل الملف ومع قاعدة البيانات)، ثم تُستورد الصفوف السليمة فقط بعد التأكيد. القالب متاح للتنزيل من صفحة الاستيراد.
- **التصدير**: يصدّر السجلات المطابقة للفلاتر الحالية، ويُسجَّل في سجل التدقيق.

## الطلبات

| من | إلى | الصلاحية |
|---|---|---|
| جديد | قيد المراجعة، محال، قيد المتابعة، منجز، متعذر | متابعة الطلبات |
| قيد المراجعة | محال، قيد المتابعة، منجز، متعذر | متابعة الطلبات |
| محال إلى الجهة المختصة | قيد المتابعة، منجز، متعذر | متابعة الطلبات |
| قيد المتابعة | محال، منجز، متعذر | متابعة الطلبات |
| منجز / متعذر | مغلق (اعتماد الإغلاق) | اعتماد إغلاق الطلبات |
| منجز / متعذر / مغلق | قيد المتابعة (إعادة فتح المغلق) | متابعة الطلبات / اعتماد الإغلاق |

- كل تغيير حالة يتطلب كتابة الإجراء المتخذ، ويُسجَّل في السجل الزمني مع المنفذ والوقت. الإحالة تتطلب الجهة المختصة، والتعذر يتطلب السبب.
- **المتأخر**: طلب مفتوح فات موعد متابعته. «الطلبات المتأخرة» تعرض الكشف وتصدّره إلى Excel.
- يعرض النظام الحالة الفعلية كما سُجِّلت، مع تنبيه ثابت بأن تسجيل الطلب لا يعني ضمان تحقيقه.

## المهام وموافقة المكلف

1. تُنشأ المهمة «بانتظار موافقة المكلف» ولا يُسجَّل عليها أي إنجاز.
2. يُسجَّل رد المكلف: **موافقة** على المهمة والموعد (تصبح تكليفاً نافذاً)، أو **طلب تعديل الموعد** (تقرر الإدارة: اعتماد الموعد المقترح أو رفضه)، أو **اعتذار** بسبب موثق.
3. بعد الاعتذار تُعاد المهمة لشخص آخر وتعود بانتظار موافقته، أو تُلغى (للمدير).
4. يمكن للمكلف الاعتذار أو طلب تعديل الموعد حتى بعد الموافقة، ويوثَّق ذلك.
5. مراحل الإنجاز: قيد التنفيذ، بانتظار رد، متعثرة (تتطلب المعوقات)، منجزة (تتطلب النتيجة النهائية). إغلاق المنجزة يعتمده المدير.
6. **المتأخرة**: تكليف نافذ لم يُنجز وفات موعده. **نسبة الإنجاز العامة** = المنجزة ÷ (الإجمالي − الملغاة).

## التنبيهات

| التنبيه | متى | من يستلمه |
|---|---|---|
| طلب جديد | فور التسجيل | من يملك صلاحية الطلبات، عدا من سجّله |
| اقتراب موعد متابعة طلب | قبل الموعد بعدد الأيام المحدد في الإعدادات (يومان افتراضياً) | المسؤول عن الطلب، أو كل من يملك الصلاحية إن لم يُحدَّد |
| تأخر طلب عن موعده | بعد فوات موعد المتابعة | كالسابق |
| إسناد مهمة جديدة أو إعادة إسنادها | فور الإسناد | من يملك صلاحية المهام، عدا المنفذ |
| اقتراب موعد إنجاز المهمة | قبل الموعد (يومان افتراضياً)، للتكليفات النافذة | من يملك صلاحية المهام |
| تأخر إنجاز المهمة | بعد فوات الموعد، للتكليفات النافذة | من يملك صلاحية المهام |
| سجلات لم تُحدَّث منذ مدة | تنبيه مجمّع أسبوعياً | مسؤول المتابعة، أو من يملك صلاحية الأشخاص للسجلات دون مسؤول |

- لا يتكرر التنبيه نفسه: مفتاح المنع يتضمن الموعد، فيتجدد التنبيه فقط إذا تغير الموعد.
- **الفحص الدوري**: يعمل احتياطياً بعد عرض الصفحات مرة كل ساعة على الأكثر. للتشغيل المنتظم يُضبط مجدول يستدعي كل ساعة:
  `POST /api/cron/notifications` مع الترويسة `Authorization: Bearer <CRON_SECRET>`، أو الأمر `npm run job:notifications`.

## التقارير

ثمانية تقارير، يتضمن كل منها الفترة الزمنية وتاريخ الإعداد ومن أعدّه والإحصائيات:
تقرير قاعدة البيانات، تقرير اكتمال البيانات، تقرير الطلبات المستلمة، تقرير الطلبات المنجزة والمتأخرة، تقرير المهام المسندة والمنجزة، تقرير المعوقات، التقرير الأسبوعي الشامل، التقرير الشهري الشامل.

- **الطباعة / حفظ PDF** من المتصفح متاحة دائماً.
- **تنزيل PDF من الخادم**: يُرسم التقرير بمتصفح Chromium فتظهر الحروف العربية متصلة واتجاه النص صحيحاً، والخط مضمَّن في الملف. يتطلب ضبط `CHROMIUM_PATH` على الخادم؛ بدونه يختفي الزر وتبقى الطباعة.
- **Excel**: ورقة للملخص وورقة لكل قسم.
- كل تصدير يُسجَّل في سجل التدقيق.
